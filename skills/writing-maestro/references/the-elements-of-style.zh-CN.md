# 中文写作的风格要素

本文件依据 William Strunk Jr. 1918 年《The Elements of Style》的编辑原则重写。原书讨论大量英语专属的所有格、代词格、分词和词法问题，逐字翻译不能直接指导中文写作。因此，本版保留“准确、清楚、简洁、有力”的核心，把规则、术语和例句改造成适用于现代中文的写作指南。

## 目录

1. 写在前面
2. 句子与标点
3. 段落与篇章
4. 常见冗余与误用
5. 校订流程

## 一、写在前面

写作先解决意思，再解决风格。作者应知道自己要说什么、说给谁听、希望读者读后知道什么或做什么。修辞不能弥补事实不清、逻辑断裂和立场含混。

这些规则不是禁令。成熟作者可以有意打破规则，但必须知道自己换来了什么。若打破规则只让句子更长、更含糊或更像模板，就没有必要。

## 二、句子与标点

### 规则 1：一句话围绕一个主要判断组织

中文可以容纳多个分句，但读者仍需看清主干。先找出“谁做了什么”或“什么是什么”，再安排条件、原因、补充和例外。

原句：考虑到系统在高峰期可能出现请求数量快速增加并且数据库连接有限的情况，我们决定通过增加缓存的方式来进行性能方面的优化。

改写：高峰期请求激增，而数据库连接数有限，因此我们增加缓存以改善性能。

### 规则 2：并列成分保持同一层级

并列的词语应在语法和意义上相称。名词与名词并列，动作与动作并列，原因与原因并列。

原句：本次改动提高了稳定性、降低延迟，以及用户更容易排查错误。

改写：本次改动提高了稳定性，降低了延迟，也让用户更容易排查错误。

### 规则 3：不要用逗号粘连所有分句

逗号不能代替逻辑。两个完整判断关系松散时，用句号或分号；关系明确时，用“因为、但、因此、同时”等连接词。

原句：接口已经停用，客户端仍在调用，错误日志持续增加，我们需要尽快处理。

改写：接口已经停用，但客户端仍在调用，导致错误日志持续增加。我们需要尽快处理。

### 规则 4：成对标点必须成对，层级必须清楚

引号、括号和书名号要闭合。括号中不要塞进决定句子主旨的信息；那类信息应回到正文。

### 规则 5：修饰语紧挨被修饰对象

长定语、状语和插入语离目标太远，会产生歧义。

原句：我们向昨天报告故障的用户发送了新的配置文件。

这句话可能指“昨天报告”，也可能指“昨天的故障”。应按真实意思重写：

- 昨天，我们向报告故障的用户发送了新配置文件。
- 我们向报告昨天故障的用户发送了新配置文件。

### 规则 6：省略主语不能牺牲责任归属

中文常省略主语，但流程、决策、故障和责任说明中，主体必须明确。

原句：经过检查后，发现配置被修改了。

改写：运维团队检查后发现，有人修改了配置。若不知道修改者，就写“配置已被修改”，不要假装知道。

### 规则 7：避免多重否定

“并非不能”“不能不说”“未尝不是”会增加解码成本。除非要表达细微语气，尽量改成正面陈述。

原句：我们不能排除该问题并非由缓存导致的可能性。

改写：该问题可能不是缓存导致的。

### 规则 8：主动句优先，但不要机械排斥被动句

主体和责任重要时，用主动句。动作承受者更重要，或主体未知、无需说明时，可以用被动句。

原句：该决定是由项目组在周一作出的。

改写：项目组周一作出了决定。

合适的被动句：三台服务器已被隔离，感染来源仍在调查。

### 规则 9：把重点放在句尾

读者通常会记住句末信息。把已知背景放在前面，把新信息或结论放在后面。

普通：真正影响交付日期的，是尚未完成的数据迁移，尽管设计稿也晚了两天。

更清楚：设计稿晚了两天，但真正影响交付日期的是尚未完成的数据迁移。

### 规则 10：标点表达关系，不制造表演

破折号适合解释和转折，省略号适合话语中断或未尽之意，感叹号表达强烈语气。它们不能替代准确措辞。正式文本中，连续感叹号、频繁破折号和无意义省略号都会削弱可信度。

## 三、段落与篇章

### 规则 11：一段处理一个中心

段落是篇章的基本单位。一个段落可以包含事实、解释、例子和结论，但它们应服务于同一中心。中心改变，就另起一段。

极短段落能强调重点，但连续使用会使文章破碎。极长段落会掩盖结构。长度应由内容决定。

### 规则 12：段首先交代方向，段尾完成推进

说明文通常适合在段首给出主题，但不必每段都写成“本段将讨论……”。段尾应完成本段任务，或自然引出下一步，不要机械复述段首。

### 规则 13：按读者需要安排顺序

常见顺序包括：

- 时间：先发生什么，后发生什么；
- 因果：原因、机制、结果；
- 问题解决：现状、问题、方案、验证；
- 总分：先给结论，再给依据；
- 空间或结构：从整体到局部，从外到内。

不要只按作者想到材料的顺序堆放内容。

### 规则 14：保持叙述视角稳定

同一段或同一摘要中，人称、时间视角和观察位置应保持稳定。确实发生转移时，用明确提示，不要在“我们、用户、你、他们”之间无缘无故跳动。

### 规则 15：同等级观点使用平行结构

平行结构能让关系一眼可见，但不要为了凑齐三项而制造内容。

不齐：方案的目标是降低延迟、稳定性提升，并让部署更简单。

齐整：方案的目标是降低延迟、提高稳定性、简化部署。

### 规则 16：删除无效的预告和总结

如果标题已经说明主题，就不必再写“下面将从三个方面展开”。如果结论自然成立，也不必写“综上所述”。预告只在长文导航中有用，总结只在信息复杂、读者确需回顾时有用。

### 规则 17：例子必须推进论点

例子不是装饰。它应解释机制、证明判断、展示边界或帮助执行。多个例子若只证明同一点，保留最有代表性的一两个。

### 规则 18：结尾给出真正的新落点

好的结尾可以回答开头的问题、说明行动、指出限制，或把论点推进一步。不要把全文逐项复述一遍，也不要突然拔高到“时代、未来、人类”。

## 四、清楚、具体、简洁

### 规则 19：使用明确、具体的语言

抽象词适合概括，具体词负责让概括落地。

空泛：用户体验得到显著改善。

具体：结账步骤从五步减到三步，放弃率下降了 12%。

写清人、时间、地点、动作、数量、条件和结果。数字需给口径，比较需给基准。

### 规则 20：删除不必要的词

简洁不是把所有句子砍短，而是让每个词都有任务。常见冗余包括：

| 冗余表达 | 更直接的写法 |
| --- | --- |
| 进行讨论 | 讨论 |
| 作出决定 | 决定 |
| 对问题进行分析 | 分析问题 |
| 在目前这个阶段 | 目前 |
| 基于……的原因 | 因为…… |
| 其主要原因是因为 | 主要因为 |
| 目的是为了 | 目的是 / 为了 |
| 涉及到 | 涉及 |
| 截止到目前为止 | 截至目前 |
| 大约十人左右 | 大约十人 / 十人左右 |
| 其中一个成员之一 | 其中一名成员 |
| 是否参加与否 | 是否参加 / 参加与否 |

### 规则 21：用动词承担动作

名词化表达常隐藏主体，让句子沉重。

原句：团队对服务进行了重启，并完成了对配置的恢复。

改写：团队重启了服务，恢复了配置。

### 规则 22：限定词必须有信息

“非常、极其、比较、相对、一定程度上、基本上、总体而言”有时必要，但常用于回避准确判断。

原句：延迟得到了非常显著的降低。

改写：P95 延迟从 800 毫秒降到 320 毫秒。

无法量化时，也应选更准确的词：“略降”“减半”“多数受访者认为”。

### 规则 23：过渡词必须说明真实关系

“因此”表示因果，“但是”表示转折，“同时”表示并行或时间重合，“此外”表示补充。不能确定关系时，不要随手加连接词。

原句：服务发生超时。此外，数据库连接池已耗尽。

若两者有因果，应写：数据库连接池耗尽，导致服务超时。

### 规则 24：先陈述事实，再给评价

“重要、惊人、有趣、成功、先进”等评价若无证据，只反映作者态度。

空泛：这是一次非常成功的发布。

具体：发布后 24 小时内没有出现 P1 故障，核心转化率提高了 4%。

### 规则 25：避免模糊指代

“这、其、该、相关、上述、前者”必须有唯一、清楚的指向。一个句子出现多个可能对象时，重复名词通常比使用代词更清楚。

### 规则 26：不要把判断冒充事实

事实可以直接核实；评价依赖标准和立场。“会议在周二举行”是事实，“这是一场高质量会议”是评价。写评价时给出标准、证据或明确归属。

### 规则 27：保留必要的限定和例外

删词不能删掉条件。“通常、在样本范围内、截至某日、在该配置下”可能决定判断是否成立。简洁不等于武断。

## 五、中文常见误用

### “的、地、得”

“的”通常连接定语与名词，“地”连接状语与动词，“得”引出动作后的程度或结果。口语化文本可以灵活处理，但不能造成歧义，也不要为了显得书面而层层叠加。

### “通过……使……”

这种结构容易让句子缺少主语。

原句：通过优化缓存，使页面加载速度提升。

改写：优化缓存后，页面加载更快。或：团队通过优化缓存，提高了页面加载速度。

### “由于……因此……”

成对使用并非永远错误，但句子短时常显重复。通常保留一个即可。

原句：由于网络中断，因此发布失败。

改写：由于网络中断，发布失败。或：网络中断，因此发布失败。

### “避免……不……”

否定范围容易写反。

错误：加强校验，避免问题不再发生。

正确：加强校验，避免问题再次发生。或：加强校验，确保问题不再发生。

### “截至”与“截止”

“截至”后接时间，表示到某个界限为止：“截至 7 月 18 日”。“截止”多作动词：“报名已截止”“报名截止到周五”。

### “制定”与“制订”

两者常可通用。“制定”偏重正式确定，常搭配政策、制度、方案；“制订”偏重起草过程。团队应优先遵循自己的术语规范，避免同一文档混用。

### “权利”与“权力”

“权利”是依法或依约享有的利益与资格；“权力”是支配和管理的力量。写制度和合同文本时尤其要分清。

### “登录”与“登陆”

进入系统或账户用“登录”；登上陆地或在某处出现用“登陆”。

### “其他”与“其它”

现代规范文本通常统一用“其他”。关键不在争论唯一正确，而在同一文档保持一致。

### “相关”

“相关人员、相关工作、相关问题”经常掩盖具体对象。知道指什么就写出来；不知道时，先补齐信息。

### “等”与“等等”

列举已经完整，或遗漏项会影响理解时，不要用“等”含糊带过。“例如”和“等”通常不必同时出现。

### “分别”

只有对应关系可能不清楚时才需要“分别”。若句式已经一一对应，可以删除。

## 六、语气与节奏

### 正式不等于僵硬

正式文本要求准确、稳定、克制，不要求把“用”改成“使用”、把“有”改成“具备”、把“是”改成“系”。选择目标读者最容易理解的正常说法。

### 口语不等于随意

自然表达仍需逻辑完整、指代清楚。口语词、网络词和缩写要符合场景，并考虑文本保存时间。

### 句长应有变化

连续长句让人疲劳，连续短句则显得急促和做作。复杂关系需要足够长度，关键结论可以短一些。朗读是检查节奏最可靠的方法之一。

### 少用虚假重音

加粗、感叹号、单句成段、反问和破折号都能制造重音。只有信息本身值得强调时才使用；否则它们会暴露作者对内容缺乏信心。

### 保持语域一致

专业报告中突然出现网络热梗，聊天文案中突然出现公文套话，都会让读者出戏。引用、角色口吻或有意反差除外。

## 七、校订流程

### 第一遍：核对意思

- 事实是否准确，有无来源？
- 结论是否由证据支持？
- 条件、范围、时间和例外是否完整？
- 作者真正想让读者知道或做什么？

### 第二遍：检查结构

- 各段是否各有中心？
- 顺序是否符合读者理解路径？
- 是否有重复段落、无效预告或机械总结？
- 标题是否真实反映内容？

### 第三遍：重写句子

- 主体和动作是否明确？
- 修饰语和指代是否清楚？
- 并列结构是否一致？
- 是否存在逗号串联、多重否定或过长定语？

### 第四遍：删减

- 删除套话、空过渡和重复限定。
- 把名词化结构改成动词。
- 把抽象评价换成事实、数字或例子。
- 相邻两句若承担同一任务，合并或删除一句。

### 第五遍：朗读

朗读时注意需要换气、回看或重新断句的地方。检查机械排比、连续短句、重复开头和不自然的书面腔。最后确认文字听起来像一个清楚的人在对目标读者说话。

## 结语

好的风格首先是对读者负责：不给模糊判断披上华丽外衣，不用冗长结构掩盖简单意思，也不靠夸张语气代替证据。先写准确，再写清楚，最后写得有节奏。能删的删，不能删的写具体。
